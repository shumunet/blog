## 前言

看到 CSP-S 2026 的 T2 讨论帖中有很多人在问正确的 `Floyd` 的循环顺序，再加上我本人其实也只是知其然却不知其所以然，于是严肃学习相关的知识，加深自己对于动态规划的理解。通过阅读此文章，你可以知道 `Floyd` 的底层原理并了解动态规划的本质。

## Floyd 算法

`Floyd` 是一个用于求解最短路问题的算法，因为它过于简单但是在图论中属于比较低效率的算法（因为图论中最短路问题大部分都是单源最短路问题），所以存在感并不高。它的代码实现其实就是下面的三重循环：

```c++
for (int k = 0; k < n; k++)
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            d[i][j] = min(d[i][j], d[i][k] + d[k][j]);
```

其中， $d_{i,j}$ 表示节点 $i$ 到节点 $j$ 的最短路。

它的思想是基于动态规划的思想：通过枚举一个中间点 $k$，如果我能花费更小的代价从 $i$ 到 $k$ 来“中转”到 $j$，那么 $i$ 到 $j$ 的最短路就被更新。这样简单的思想也就带来了一个很大的误区：很多人认为循环中 `i,j,k` 甚至其他的排列方式都是可以的，但其实**必须将 $k$ 放在最外层循环。**

为什么会这样呢？我们刚刚提到 `Floyd` 的本质其实就是动态规划，动态规划如果要更新一个的状态的话，它所依赖的状态必须是已经更新完毕的。在 `Floyd` 算法中其实就是更新第 $k$ 层需要第 $k-1$ 层更新完毕。当外层固定更新 $k$ 的时候， $d_{i,k}$ 和 $d_{k,j}$ 都是只允许通过 $k-1$ 个点的最短路，只不过最外层用滚动数组压掉了。但是如果 $k$ 不在最外层，就会出现以下问题：

- 某个 $d_{i,k}$ 还没有被更新到正确值；
- 某个 $d_{k,j}$ 被混入了不该在当前阶段使用的信息；
- 导致某个路径需要“回头再用之前已经处理完的起点/终点”，但循环已经结束，无法再次松弛。

举个例子，我们考虑如下有向图：

```
0 -> 2 权重 1
2 -> 1 权重 1
1 -> 3 权重 1
0 -> 3 权重 100
```

正确的最短路显然是：

```
0 -> 2 -> 1 -> 3 = 3
```

但是如果我们循环层序是错的，也就是下成下面的代码：

```c++
for (int i = 0; i < n; i++)
    for (int k = 0; k < n; k++)
        for (int j = 0; j < n; j++)
            d[i][j] = min(d[i][j], d[i][k] + d[k][j]);
```

那么当 $i=0$ 时候，就会有：

- $k=1$ 时，$d_{0,1}=INF$，无法松弛；
- $k=2$ 时，会更新 $d_{0,1}=2$，但是此时的 $d_{2,3}$ 还没通过 $1$ 更新成 $2$，导致更新 $d_{0,3}$ 失败；
- 接下来，因为 $i=0$ 已经处理完了，$d_{0,3}$ 无法继续被更新。

## 动态规划层序选择

### 基本原理

根据刚刚卡掉 `Floyd` 错误层序，我们会发现动态规划更新状态时要求它的前置状态一定是更新好的，否则就会出现问题。因此，有个一句话原则很好用：**循环顺序必须是 DP 依赖图的一个拓扑序。**

这句话是什么意思呢？就是计算某状态时，它依赖的所有状态必须已经是最终值。其他一切规则都是这句话的推论。

在蓝书中，动态规划被要求写成如下层序：阶段 / 状态 / 转移。

| 角色     | 含义                                   | 通常位置 |
| -------- | -------------------------------------- | -------- |
| **阶段** | 把问题按“规模”分层，层与层之间单向依赖 | 最外层   |
| **状态** | 当前层内的状态维度                     | 中间     |
| **转移** | 枚举决策/子结构                        | 最内层   |

这是因为后面的层依赖于前面的层算完。例如 `Floyd` 的 $k$，`区间 DP` 的 $len$，背包的物品编号等等都属于阶段。

### 线性 DP

以线性动态规划为例，依赖方向会决定顺序。

```c++
dp[i][j] = f(dp[i-1][j], dp[i][j-1])
```

因为 `dp[i][j]` 依赖左上和左边，正序保证它们已算好。

接下来就是滚动数组，这是最容易错误的地方，因为原地更新时要看依赖方向。

例如在 `0/1 背包` 和 `完全背包` 中，经过滚动数组优化后转移方程都是：

```c++
dp[j] = max(dp[j], dp[j-w] + v)
```

但是在滚动数组前，`0/1 背包`  依赖于 $dp_{i-1,j-w}$，这导致滚动后的 $j$ 必须要逆序，否则 $dp_{j-w}$ 就会被本行覆盖掉，就会出现错误。

而 `完全背包` 则依赖于 $dp_{i,j-w}$，这是本行的结构，就导致 $j$ 必须要正序，否则 $dp_{j-w}$ 就不会受到本行数据更新的影响，同样出现错误。

**同一个转移方程，层序方向不同，含义就不同。**

### 区间 DP

在区间动态规划中，则是采用按长度分层的方式，$dp_{l,r}$ 依赖更短的区间。

所以外层必须是 $len$，而不能是别的，不然 $dp_{l,r}$ 依赖的 $dp_{l,k}$ 和 $dp_{k+1,r}$ 都没有被正确更新，这样就会出现问题。

### 树形 DP 与 DAG DP

此类动态规划问题因为常常依赖于搜索算法来遍历，所以要求上一个状态必须更新完成我们可以采用下面的策略：

- 树：后序 DFS（先算子树），因为子树更新完就不会被继续更新了。或者上记忆化；
- DAG：按照拓扑序进行，或者上记忆化。

### 状压 DP

这就要按照集合大小或者按位进行了。`for (mask) for (i)` 通常可行，因为 $mask$ 的子集 $mask_{i}$ 一定比 $mask$ 小（按二进制数值也成立）。但**枚举子集**时要保证子集已算完，通常 `for (mask) for (sub = mask; ...)` 是安全的。

## 总结

根据本篇文章不难发现，动态规划的遍历顺序是会影响到一个动态规划算法的正确性的。但是只要是按照被更新值所依赖的前置值都被计算完全这个基础原则就一定不会错。**记忆化搜索是万能兜底**，它自动按依赖关系递归，不存在层序问题。先写记忆化搜索跑对，再照它的依赖方向改写成递推，层序基本就出来了。（其实记忆化搜索的本质就是动态规划的递归实现。）
